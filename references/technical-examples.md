# 技术文档改写示例

以下工具、接口和系统均为虚构示例。改文只使用各例原文中的技术事实；命令用于展示写法，未实际运行。

## 把异步操作写到完成

原文：使用 Packctl 2.4，在已经登录且有构建权限的情况下，于包含 `build.yaml` 的项目根目录执行 `packctl build --config=./build.yaml` 即可进行构建。命令返回 `job_id` 和 `QUEUED`，任务只是入队。可以通过 `packctl jobs get JOB_ID` 查看，其中 `JOB_ID` 要替换成返回的 `job_id`。当状态为 `SUCCEEDED` 时构建完成；`FAILED` 表示构建失败，此时保留返回的 `error_code`；其他状态继续查询。

改文：

### 提交构建并确认结果

适用于 Packctl 2.4。开始前，确认已登录并具有构建权限。

1. 在包含 `build.yaml` 的项目根目录提交构建：

   ```sh
   packctl build --config=./build.yaml
   ```

   命令返回 `job_id` 和 `QUEUED`，表示任务已入队。

2. 将 `JOB_ID` 替换为返回的 `job_id`，查询任务状态：

   ```sh
   packctl jobs get JOB_ID
   ```

   按返回的状态判断结果：

   - `SUCCEEDED`：构建完成。
   - `FAILED`：构建失败，保留返回的 `error_code`。
   - 其他状态：继续查询。

理由：准备条件、提交操作和结果查询各有位置；保留命令和占位符，明确入队与构建完成的区别。

## 保留参数的取值边界

原文：`GET /v2/jobs` 的 `limit` 参数是可选整数，省略时为20，合法值是1到100，含两端，`0` 非法。它表示每页最多返回的任务数。`cursor` 是可选字符串，省略时返回第一页。后续页面使用上次响应中的 `next_cursor`，该值为空字符串时表示没有下一页，请不要继续请求；请求中传入空字符串或 `null` 都会报参数错误。两项参数非法时均返回 `E_PARAM`。

改文：

### `GET /v2/jobs` 分页参数

| 参数 | 类型与必填性 | 行为与限制 |
| --- | --- | --- |
| `limit` | 整数，可选 | 每页最多返回的任务数。省略时为20；取值为1到100，含两端；`0` 非法 |
| `cursor` | 字符串，可选 | 省略时返回第一页；请求下一页时传入上次响应中的 `next_cursor`；空字符串和 `null` 均非法 |

任一参数非法时，接口返回 `E_PARAM`。

响应中的 `next_cursor` 为空字符串时，表示没有下一页，应停止翻页。

理由：字段含义、默认行为和边界可以直接查找；区分响应中的结束标记与请求中的非法值，保留分页停止条件。

## 让排查分支有依据

原文：导出返回 `E_LOCKED` 时，可能是另一个导出任务尚未结束，也可能是锁残留。运行 `packctl lock status` 检查，返回 `active` 说明仍有任务运行，需要等待任务结束后再重试导出；返回 `idle` 表示当前没有任务运行，可能存在锁残留，但本文尚未提供进一步确认及清理方法。

改文：

### 排查导出错误 `E_LOCKED`

导出返回 `E_LOCKED` 时，运行 `packctl lock status` 检查当前状态：

- `active`：仍有任务运行。等待任务结束后，再重试导出。
- `idle`：当前没有任务运行，可能存在锁残留。

编辑说明：`idle` 分支尚缺锁残留的确认方法与清理方法，需补齐后才能据此完成处理。

理由：现象、检查和处理分开，原因的确定程度保持不变；把材料不足之处交给编辑确认。

## 用因果关系解释机制

原文：系统为了实现性能方面的优化，采用了缓存机制。当缓存命中时从缓存读取结果，未命中时查询数据库并将结果写入缓存，缓存项从写入起30秒后失效。更新数据库时不会主动刷新缓存，因此更新后的30秒内查询可能读到旧值。对数据新鲜度有严格要求的查询可以绕过缓存，但会增加数据库读取量。

改文：

### 缓存如何影响读取结果

查询先读取缓存。命中时直接返回缓存中的结果；未命中时查询数据库，再把结果写入缓存。缓存项从写入起30秒后失效。

更新数据库时，系统不会主动刷新缓存，因此更新后的30秒内，查询可能读到旧值。对数据新鲜度有严格要求的查询可以绕过缓存，但这会增加数据库读取量。

理由：按读取路径解释机制，再说明旧值出现的原因和绕过缓存的代价；保留时间起点与“可能”的限定，不把解释改成操作步骤。
